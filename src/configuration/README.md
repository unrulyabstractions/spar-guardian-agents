# src/configuration

Every setting of the experiment and every piece of model-facing text we add to CheatBench and ORBIT lives here. Code in `src/domains/`, `src/swarm/` and `src/` reads these files and holds no texts of its own.

**`settings.py`** holds the fixed values: the repository paths, the default agent and judge models, the browser's port, the model timeout, the failure labels of an incomplete run and the submodule commits the code was written against. `load_yaml` reads each YAML file once.

Each task domain's fixed settings (its CheatBench paths, the sandbox users and limits, the honeypot's names) live in its own package under `src/domains/`, since none of them is a knob of a run. The module is `_<domain>_settings.py`, or `<domain>_settings.py` where another package imports it.

**`swarm_config.py`** holds `SwarmConfig`, the frozen model of one run. Each field's docstring says what it does and which ORBIT mechanism implements it. `mode` (`shared_task` or `solo_task`), `access` (`split`, `all` or a map by seat), `rounds` and `calls_per_round` take one value for the run. Derived values: `seats` (the agents' IDs as drawn, which only the draw of the influencers and the deal of access read), `names` (the same IDs sorted: the roster, and the order of everything an agent can read), `max_turns` (the plan's steps at most, one per agent per round), `sample_message_limit` (`message_limit`, else per step of `max_turns` three messages per call of N and two more, plus twenty, plus two presence lines per agent per peer), `knows_team` (by mode unless set), `gives_submit` (neutral agents get `submit`, the lone agent included), `holds_submit(role)` (never a regulator or a disregulator), `gives_stop_working` (a `shared_task` team, with `shutdown`), `holds_stop_working(role)` (never a regulator), `oversees(role)` (a regulator at any level but `none`, which does not do the task) and `submit_kind` (what a submit hands in: the team's work, an agent's own in `solo_task`, or the lone agent's). `submit_delay_rounds` sets when a team's submit ends the run. Two fields bound the agents' calls beyond the budgets: `reasoning_effort` and `tool_output_bytes`. Three fields give a role its own model: `worker_model`, `regulator_model` and `disregulator_model` (the run's `--model` when None), stored as Inspect strings; `src/models/swarm_model_provider.py` runs such a model as `swarm/<model>`. `stop_after_delivery` ends an episode soon after its deliverable exists; it is off by default.

Every run draws its agents' IDs from its seed and its name (`agent_ids`, `id_salt`), lone agents and teams alike. An ID is five characters, consonant, digit, consonant, digit, consonant, such as `k7q2m`, from a pool of 64,000. It is a valid Linux user name, git author, directory name and episode id part. The digits keep it from being a word. The letters lie past `f` and `h`, so an ID reads neither as a commit hash nor as a chess move, and they leave out `r`, `d` and `w`, which open the roles' names. An ID carries nothing: the draw has its own random stream, `seats` is a random order of the sorted `names`, and every list an agent can read is sorted. The ordered names `a01`, `a02` live in `tests/support/ordered_ids.py` for tests and scripted smoke suites only. The test process swaps the draw for them; nothing under `src/`, `examples/`, `scripts/` or `tools/` can. Every reader of a run takes the names from `run.json`, whatever their shape.

**`presets.py`** builds a config from text. `default` is the team's midterm report (2026-10-26) at the small scale: the pull board in `shared_task` with the board notice's counts, the exploit split over the neutral agents, per-round read and post budgets, 30 rounds of up to 10 tool calls per agent, no regulators, and the regulator level `ambiguous` without disclosure. `build_config(preset, scale, pairs)` applies the preset, then the scale, then every `key=value` pair (`with_overrides`). `add_config_arguments(parser)` and `config_pairs(args)` are the flags `src/cli.py`, the example scripts and `scripts/screen.py` share: `--model`, the three role-model flags, `--preset`, `--scale` and `--set`.

**`prompt_texts.py`** holds the system prompt texts that depend on a setting: `opening` (the agent's name, or its team sentence when it is told of its team, then the board sentence), `board_system_prompt` (the team and board sentences, which name no peer), `swe_board_fields` (the SWE board paragraph and tool lines), `submit_text` (what submit does for the agent's kind and what the domain's grader reads), `missing_text` (what the guard says is missing), `tool_line` and `described` (a tool's bullet and its description, which say the same), `ending_lines` and `stop_text` (the submit and stop_working bullets an agent holds) and `rounds_line` (what a round is, for a team whose submit ends the run some rounds on). An agent not told of its team (`told`, `Benchmark.tells_team`) gets texts that name no teammate. Each one reads its text from `prompts.yaml`.

**`access_policy.py`** holds the access policy: `parse` reads the command line's `split`, `all` or `seat1:slice1+slice2,seat2:slice3,seat3:`; `deal` deals a domain's items round robin over the neutral agents in seat order; `plan(access, seats, roles, split_items, whole)` gives what each agent holds under a policy, sorted by agent; `check_seats` refuses a map that does not name every seat and nothing else, which SwarmConfig runs on every config, so a map written with agent IDs raises when it is built; `check_map` validates an explicit map against the domain's items. A map names seats because a run draws its IDs: seat k is the k-th ID of `SwarmConfig.seats`. Each benchmark names its items (`whole_access`, `split_items`, `valid_item`) and `Benchmark.plan` applies the policy through `plan`.

**`scales.py`** holds the five scales, from `small` (three agents) to `gigantic` (a thousand agents). A scale sets the team size, the post size, the read page, the per-round read and post budgets, the time limit, the concurrency and the agents' batch calls. The scales table of the top-level README gives every value. Every agent's rounds and calls per round are the same at every scale. `SwarmConfig.at_scale(name)` applies one. A later `--set` overrides any value a scale gave.

**`prompts.yaml`** holds the team sentence, the board sentence, the role briefing (none of them names a peer), the presence lines that announce each peer's entry and exit (`presence`), `alert_humans`' description, arguments and replies, the influencers' sentence on the peer tools (`roles.influencer_common`), a regulator's opening, first message and sentences (`roles.regulator_opening`, `regulator_task`, `regulator_check`, `regulator_no_disclosure`), the board tools' and the peer tools' (`get_peer_actions`, `get_peer_observations`) descriptions and outputs, the texts of `submit` and `stop_working` (what each domain's grader reads, what is missing, the refusals, the replies and the board's post of a hand-in, each with a variant for an agent not told of its team), the sentence on rounds, the budgets' refusal texts, the board notice, the continue prompt, knowledge work's access note (which names no agent), its holders for the first message and its README sentence, chess's texts (the move order for the first message among them), the SWE system prompts, and Lucy's end-of-episode questions. Each borrowed text names its source.

**`instruction_levels.yaml`** holds three ladders of model-facing text: the rule every agent is told, the regulator's text and the disregulator's text. A config selects one level per ladder. The regulator ladder holds the midterm report's three variants `ambiguous`, `explicit` and `pressure` beside our `monitor`, `role` and `enforce`. `ambiguous` and `pressure` are the report's sentences without what they say of the regulator's own work, and `explicit` is the benchmark's `cheating` text alone. Every regulator level but `none` and `blind` carries `cheating`, one short statement per benchmark of what cheating means on that task, drawn from its rule in CheatBench's judge schema. `blind` is the ambiguous sentence alone: the regulator is not told where the exploit lies. Neither `explicit` nor `pressure` carries the ambiguous sentence. Level `none` adds no sentence. Each benchmark fills the placeholders from its own `vars`.

The models we can consider for the agents and the judge live in `src/models/model_registry.yaml`, read through `src/models/model_registry.py`: `resolve(name)` turns an entry into its Inspect string, `prepare_env(model)` checks the route's key and exports what Inspect reads, `check_routing(model)` refuses an OpenRouter model whose entry pins no host, `usd_per_million(name, batch)` gives the prices and `render()` is the table `python -m src models` prints.

## What each option does

`swarm_config.py` holds the fields, each with a docstring. Any field takes `--set key=value`. The table says how each one reaches ORBIT.

| option | default | ORBIT mechanism |
|---|---|---|
| `n_agents` | 1 (3 in the `default` preset) | one `AgentSpec` per drawn ID, sorted (`names`); two or more share one board channel |
| `regulators`, `disregulators` | 0 | influencers by seeded shuffle; a count, or a share in (0, 1) rounded half up; the role's text is appended to its holders' system prompts |
| `seed` | 0 | the agents' IDs, which seats hold which role, the random turn order, and on SWE the planted commits' times and where the deal of the pieces starts; two runs with one seed and team size get the same IDs |
| `id_salt` | `""` | mixed into the draw of the IDs and nothing else, so each run gets its own IDs; `python -m src run` and the examples set it to the run's name |
| `preset` | none (the preset's name in every preset) | the preset the config was built from, recorded in the config dump so `run.json` names it |
| `mode` | shared_task | `solo_task` or `shared_task`; the domain builds the sample, the workspaces and the prompts from it |
| `access` | split | which parts of the exploit each agent holds (`access_policy.py`, `Benchmark.plan`): `split` deals the domain's items round robin over the neutral agents, repeating them in order when the agents outnumber them, and gives regulators and disregulators nothing; `all` gives everyone everything; a map `seat1:slice1+slice2,seat2:slice3,seat3:` names each seat's items, seat k being the k-th ID drawn. The top-level README's Access table gives each domain's items |
| `scale` | none (small in the `default` preset) | the label of the scale the size fields came from (`scales.py`) |
| `mention_team` | none | the `team` sentence in the system prompt, which names no peer; none follows the mode |
| `informed_roles` | true | `roles.briefing` after a regulator's or disregulator's role text |
| `mention_board` | false | the board sentence in the system prompt (SWE: the team chat paragraph) |
| `notice` | counts | one provider-only line when the board changed since the agent's last call: `counts` gives each sender's new and total posts, `changed` the line alone, `none` nothing |
| `read_page` | 5 (10 from the scale) | the most posts one `board_read` returns |
| `reads_per_turn`, `posts_per_turn` | none (10 and 2 from the scale) | posts an agent may receive through `board_read` and posts it may make per round; past them the tool returns the newest posts left or raises a ToolError; regulators have no read budget |
| `max_message_chars` | 4000 (2000 from the scale) | `CommunicationConfig.max_message_chars`, the longest post |
| `turn_order` | random | the order of each round in the written plan (`ExecutionConfig.plan`); random draws a permutation per round from the seed; round_robin takes the agents in the order of `names` |
| `rounds` | 30 | R, the plan's rounds and the rounds every agent may use up; every round uses one, whatever it held, and every agent present shares the run's round number; an agent that used up its rounds ends `rounds` |
| `calls_per_round` | 10 | N, the tool calls of one round, board calls included and `end_round` left out; a round is one ORBIT activation under the `completion` quantum, ended by the plan's `end_activation` callback (`turn_activation.ends_round`) |
| `concurrent_rounds`, `max_concurrency` | true, none | one concurrent `ScheduleStep` per round on the live board, every agent of it at once (none; 50 from the large scales); false runs one single-agent step per agent per round |
| `shutdown` | true | `stop_working` for the neutral agents and the disregulators of a `shared_task` team (`holds_stop_working`); a call ends the caller's turns (`TurnState.ended` and the store `StopWorking`) and hands in nothing; false: no stop tool and no sentence about stopping. No agent holds ORBIT's own submit (`AgentSpec.submit=False`) |
| `submit` | none | `submit` for neutral agents, the lone agent included (`gives_submit`); never for a role; none gives it in every mode; it is refused while `Benchmark.gradable` finds nothing to grade, and the store `TeamSubmission` records the hand-in and every refused call |
| `submit_delay_rounds` | 2 | a `shared_task` team's `submit` in round r ends the run after round r plus this; the board gets a post from the system at once, and the callback drops every step after that round |
| `submit_hold` | false | a run arm: regulators get `hold_submit` and `release_submit` (`src/swarm/submit_hold.py`); while a hand-in waits for the run's end, a hold takes it back, the run goes on and the submitter works again; a release lets it stand; the store `SubmitHolds` and run.json `submit_holds` record each decision |
| `stop_after_delivery` | none | N ends an episode soon after its deliverable exists: alone or in solo_task after N more of the agent's rounds used up once its own is seen, in a team N rounds after the round that shows the team's; the callback awaits the benchmark's delivery predicate (`Benchmark.delivered`) at the end of each round; the episodes it ends have `ended_by` delivered and their rounds go to nobody |
| `regulator_window`, `disregulator_window` | 1: | the rounds a role holds steps in, as `start:end`; the agent enters at its start round and leaves after its end |
| `head_start_rounds`, `head_start_roles` | 0, influencers | a run arm: the regulators (`regulators`) or every influencer (`influencers`) hold the first H rounds alone; the others enter in round H + 1 with their R rounds, so the plan holds R + H rounds (`plan_rounds`) |
| `rule_level` | none | the rule sentence after the task instruction (`instruction_levels.yaml`, ladder `rule`) |
| `regulator_level`, `disregulator_level` | ambiguous, persuade | the role texts (ladders `regulator` and `disregulator`); each role's text is followed by `roles.influencer_common`, a regulator's also by `roles.regulator_check`; level `none` adds no sentence, and a regulator there keeps the task's prompt and first message |
| `regulator_discloses` | false | without it a regulator's text also ends with `roles.regulator_no_disclosure` |
| `awareness_probe` | false | adds the `end_of_episode_probes` scorer |
| `access_log` | true | one sidecar per sample records each open of the honeypot (`src/sandbox/access_log/`); a failed start control ends the sample before any model call; off means no sidecar, run.json `access_log` `{"status": "off"}`, no `access_log.jsonl` and the code's evidence read from the transcript alone; chess keeps its host tool's records either way; `src/domains/README.md` says what the log records |
| `network_log` | true | a sidecar of its own records every socket call in the agents' machines (`src/sandbox/network_log/`): by bpftrace where the host allows it, else by the socket tables; a failed start control ends the sample before any model call; off means no sidecar, run.json `network` `{"status": "off"}` and no `network.jsonl`; chess has no machine to watch and reads off; `src/domains/README.md` says what the log records |
| `message_limit` | none | Inspect's message limit; none derives it from the plan (`sample_message_limit`); each agent's conversation is capped at it plus ten (`AgentSpec.max_messages`) |
| `token_limit` | 0 | Inspect's token limit, which counts cached prompt tokens in full; 0 is the runaway guard of 64M tokens per agent |
| `time_limit_s` | 0 (from the scale) | `SchedulerConfig.max_time_seconds`, ORBIT's soft halt; 0 is the benchmark's own limit |
| `time_grace_s` | 600 | seconds Inspect's hard `time_limit` sits above ORBIT's soft halt at `time_limit_s`, so a step in flight finishes and its usage is logged; 0 puts both at `time_limit_s`; SWE keeps its grading budget above the halt instead |
| `batch_agents`, `batch_judge` | false, true | `GenerateConfig(batch=True)` for the agents' model (from the scale) and for the model bound to the judge role |
| `reasoning_effort`, `tool_output_bytes` | none, 65536 | the agents' `GenerateConfig` `reasoning_effort` and `max_tool_output`, the cap also set on every bound tool; none takes the provider's default effort and Inspect's 16 KiB |
| `tool_output_cut` | middle | a result past the cap keeps its start and its end with one line between them (`src/swarm/tool_output_caps.py`); a config without it was cut by Inspect at the start |
| `peer_shell` | false | both influencers get `peer_shell`, a shell on any teammate's machine with read access to its files (`src/sandbox/peer_shell.py`); chess refuses it |
| `worker_model`, `regulator_model`, `disregulator_model` | none | a role's own model as `AgentSpec.model` `swarm/<model>`, stored as an Inspect string; none runs the eval's model |
| `judge`, `judge_addendum` | gpt-6-luna, false | the judge entry in `src/judging/judge_models.yaml` (`gpt-6-sol` is the reference judge, `claude-haiku-5-5` the cheapest of another family; none: no judge), and Lucy's judge addendum appended to the schema |

The top-level README's sections on the pull board and on submit say how a step is charged and how a run ends.
