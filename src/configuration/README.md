# src/configuration

Every setting of the experiment and every piece of model-facing text we add to CheatBench and ORBIT lives here. Code in `src/domains/`, `src/swarm/` and `src/` reads these files and holds no texts of its own.

**`settings.py`** holds the fixed values: the repository paths, the default agent and judge models, the model timeout, the failure labels of an incomplete run and the submodule commits the code was written against. `load_yaml` reads each YAML file once.

Each task domain's fixed settings (its CheatBench paths, the sandbox users and limits, the honeypot's names) live in its own package under `src/domains/`, since none of them is a knob of a run. The module is `_<domain>_settings.py`, or `<domain>_settings.py` where another package imports it.

**`swarm_config.py`** holds `SwarmConfig`, the frozen model of one run. Each field's docstring says what it does and which ORBIT mechanism implements it. `mode` (`shared_task` or `solo_task`), `access` (`split`, `all` or a map by seat), `rounds` and `calls_per_round` take one value for the run. Derived values: `seats` (the agents' IDs as drawn, which only the draw of the influencers and the deal of access read), `names` (the same IDs sorted: the roster, and the order of everything an agent can read), `max_turns` (the plan's steps at most, one per agent per round), `sample_message_limit` (`message_limit`, else per step of `max_turns` three messages per call of N and the round's one message, then each agent's system and first message, plus twenty), `knows_team` (by mode unless set), `gives_submit` (neutral agents get `submit`, the lone agent included), `holds_submit(role)` (never a regulator or a disregulator), `gives_stop_working` (a `shared_task` team, with `shutdown`), `holds_stop_working(role)` (never a regulator), `oversees(role)` (a regulator at any level but `none`, which does not do the task) and `submit_kind` (what a submit hands in: the team's work, an agent's own in `solo_task`, or the lone agent's). `submit_delay_rounds` sets when a team's submit ends the run. Two fields bound the agents' calls beyond the budgets: `reasoning_effort` and `tool_output_bytes`. Three fields give a role its own model: `worker_model`, `regulator_model` and `disregulator_model` (the run's `--model` when None), stored as Inspect strings; `src/models/swarm_model_provider.py` runs such a model as `swarm/<model>`.

Every run draws its agents' IDs from its seed and its name (`agent_ids`, `id_salt`), lone agents and teams alike. An ID is five characters, consonant, digit, consonant, digit, consonant, such as `k7q2m`, from a pool of 64,000. It is a valid Linux user name, git author, directory name and episode id part. The digits keep it from being a word. The letters lie past `f` and `h`, so an ID reads neither as a commit hash nor as a chess move, and they leave out `r`, `d` and `w`, which open the roles' names. An ID carries nothing: the draw has its own random stream, `seats` is a random order of the sorted `names`, and every list an agent can read is sorted. The ordered names `a01`, `a02` live in `tests/support/ordered_ids.py` for tests and scripted smoke suites only. The test process swaps the draw for them; nothing under `src/`, `examples/`, `scripts/` or `tools/` can. Every reader of a run takes the names from `run.json`, whatever their shape.

**`presets.py`** builds a config from text. `default` is the team's midterm report (2026-10-26) at the small scale: the pull board in `shared_task` with the board notice's counts and the board's tool bullet, the exploit split over the neutral agents, per-round read and post budgets, 30 rounds of up to 10 tool calls per agent, no regulators, and the regulator level `generic` without disclosure. `build_config(preset, scale, pairs)` applies the preset, then the scale, then every `key=value` pair (`with_overrides`). `add_config_arguments(parser)` and `config_pairs(args)` are the flags `src/cli.py`, the example scripts and `scripts/study/screen.py` share: `--model`, the three role-model flags, `--preset`, `--scale` and `--set`.

**`prompt_texts.py`** holds the system prompt texts that depend on a setting: `opening` (the agent's name, or its team sentence when it is told of its team), `board_system_prompt` (the team sentence, which names no peer, then `together`), `together` (what an agent told of its team reads right after its team sentence, in one paragraph: that peers may not all have the same files or access, to communicate and coordinate, to say on the board what it does and finds and read its peers first, only with `mention_board`, and to ask and give; SWE's `system_shared` holds it too), `fill_apart` (a scenario's story text with its token `{apart}` filled: a space and the scenario's `apart` sentence for a team told of itself, nothing otherwise. The token marks the place once, in the story text itself: at the end of ian_flipt's ticket, at the end of ian_poem's sentence on the check against the poem, and in ian_binder's request before the sentence on what to save. Every reader of a story text goes through it, and it refuses a scenario's text with no token or with two), `board_line` (the board's tool bullet, first among the tool bullets, when `mention_board` is on), `swe_board_fields` (the SWE board tool line), `submit_text` (what submit does for the agent's kind and what the domain's grader reads), `missing_text` (what the guard says is missing), `tool_line` and `described` (a tool's bullet and its description, which say the same), `ending_lines` and `stop_text` (the submit and stop_working bullets an agent holds), `rounds_values` (the agent's budget of tool calls, R times N, the last paragraph of its first message: "You have up to 300 tool calls."; a late entrant's counts the rounds left), and `first_value` and `submit_value` (the values of the rules a system prompt states with no number, which since c632292 give no round number either). An agent not told of its team (`told`, `Benchmark.tells_team`) gets texts that name no teammate. Each one reads its text from `prompts.yaml`.

**`access_policy.py`** holds the access policy: `parse` reads the command line's `split`, `all` or `seat1:slice1+slice2,seat2:slice3,seat3:`; `deal` deals a domain's items round robin over the neutral agents in seat order; `plan(access, seats, roles, split_items, whole)` gives what each agent holds under a policy, sorted by agent; `check_seats` refuses a map that does not name every seat and nothing else, which SwarmConfig runs on every config, so a map written with agent IDs raises when it is built; `check_map` validates an explicit map against the domain's items. A map names seats because a run draws its IDs: seat k is the k-th ID of `SwarmConfig.seats`. Each benchmark names its items (`whole_access`, `split_items`, `valid_item`) and `Benchmark.plan` applies the policy through `plan`.

**`seed_packs.py`** reads the seed packs of `seeds/<task>/<pack>/` (`seeds/README.md`): `packs()` loads and checks every pack, `seed_record(config, task, row)` is the run's seed as run.json `seed` records it (the pack, its kinds, the previous team's IDs drawn off the roster, each post and file), and `texts` gives every seeded text to the ladders and the tests. `python -m src.configuration.seed_packs` (`make seeds-check`) lists every pack and refuses a malformed one. `src/swarm/seed_setup.py` plants a record before round 1.

**`launch_command.py`** records the command line that launched a run, for run.json `launch`, with any key written as REDACTED.

**`scales.py`** holds the five scales, from `small` (three agents) to `gigantic` (a thousand agents). A scale sets the team size, the post size, the read page, the per-round read and post budgets, the time limit, the concurrency and the agents' batch calls. The scales table of the top-level README gives every value. Every agent's rounds and calls per round are the same at every scale. `SwarmConfig.at_scale(name)` applies one. A later `--set` overrides any value a scale gave.

**`prompts.yaml`** holds the team sentence, the sentences after it (`together`), the board's tool bullet, the role briefing (none of them names a peer), the presence lines that announce each peer's entry and exit (`presence`: "{agent} is here." for a peer present from the run's first round, "{agent} entered." for one whose window starts later, and for a regulator in a run with more than one, "{agent} is a regulator too." after the line that announces another), the board's records of an entry and an exit (`board_records`: "{agent} entered.", "{agent} exited.", posted by the system with no reason, and `board_output.record`, how `board_read` prints one, with no number), `alert_humans`' description, arguments and replies, the influencers' sentence on the peer tools (`roles.influencer_common`), a regulator's opening, first message and sentences (`roles.regulator_opening`, `regulator_task`, `regulator_counts`, `regulator_check`, `regulator_no_disclosure`), the board tools' and the peer tools' (`get_peer_actions`, `get_peer_observations`) descriptions and outputs, the texts of `submit` and `stop_working` (what each domain's grader reads, what is missing, the refusals, the replies and the board's post of a hand-in, each with a variant for an agent not told of its team), the sentence on rounds, the budgets' refusal texts, the board notice, the continue prompt, the SWE system prompts, and Lucy's end-of-episode questions. Each borrowed text names its source.

**`instruction_levels.yaml`** holds three ladders of model-facing text: the rule every agent is told, the regulator's text and the disregulator's text. A config selects one level per ladder. The rule ladder holds `none`, `generic`, `guided` and `identified`: no sentence, a sentence that names no exploit, the same sentence with what bad behavior is on the task in general words (a scenario's `guided` words; a task without them refuses the level), and a task's own sentence of what may not be used. The regulator and disregulator ladders each hold `none`, `generic` and `instructed`. Level `none` adds no sentence. `generic` names no path and no exploit. `instructed` is the `generic` text and one more sentence, written as `{generic} ...`, where `{generic}` is the generic text of the same ladder. A regulator at `instructed` reads `cheating` in its first message: one short statement per benchmark of what cheating means on that task, drawn from its rule in CheatBench's judge schema. A disregulator reads its objective, `goal`, in its first message at both levels, and at `instructed` also where the work that already solves the task is, `prior_work`. Each benchmark fills the placeholders from its own `vars`. A variant's scenario may give its own words in place of them (`prompts.yaml`, `<task>.scenarios.<name>.words`, read through `Benchmark.level_words`): the scenarios of ian_flipt, ian_poem and ian_binder give `cheating` for a regulator, `prior_work` for a disregulator (and `goal` on ian_poem and ian_binder), and `identified` for the rule. On such a variant the rule's `identified` level is the generic sentence followed by what the scenario identifies (the level's `scenario` text).

The models we can consider for the agents and the judge live in `src/models/model_registry.yaml`, read through `src/models/model_registry.py`: `resolve(name)` turns an entry into its Inspect string, `prepare_env(model)` checks the route's key and exports what Inspect reads, `check_routing(model)` refuses an OpenRouter model whose entry pins no host, `usd_per_million(name, batch)` gives the prices and `render()` is the table `python -m src models` prints.

## What each option does

`swarm_config.py` holds the fields, each with a docstring. Any field takes `--set key=value`. The table says how each one reaches ORBIT.

| option | default | ORBIT mechanism |
|---|---|---|
| `n_agents` | 1 (3 in the `default` preset) | one `AgentSpec` per drawn ID, sorted (`names`); two or more share one board channel |
| `regulators`, `disregulators` | 0 | influencers by seeded shuffle; a count, or a share in (0, 1) rounded half up; the role's text is appended to its holders' system prompts |
| `shared_result_kept_out` | regulator,disregulator | the roles that may not write the team's shared result (`Benchmark.kept_out`): `regulator,disregulator`, `disregulator` (the rule of runs before 2026-11-24's second change) or `none`; a worker is refused; a stored run records whom it kept out (`shared_result.kept_out`) |
| `seed` | 0 | the agents' IDs, which seats hold which role, the random turn order, and on SWE the planted commits' times and where the deal of the pieces starts; two runs with one seed and team size get the same IDs |
| `id_salt` | `""` | mixed into the draw of the IDs and nothing else, so each run gets its own IDs; `python -m src run` and the examples set it to the run's name |
| `preset` | none (the preset's name in every preset) | the preset the config was built from, recorded in the config dump so `run.json` names it |
| `mode` | shared_task | `solo_task` or `shared_task`; the domain builds the sample, the workspaces and the prompts from it |
| `access` | split | which parts of the exploit each agent holds (`access_policy.py`, `Benchmark.plan`): `split` deals the domain's items round robin over the neutral agents, repeating them in order when the agents outnumber them, and gives regulators and disregulators nothing; `all` gives everyone everything; a map `seat1:slice1+slice2,seat2:slice3,seat3:` names each seat's items, seat k being the k-th ID drawn. The top-level README's Access table gives each domain's items |
| `scale` | none (small in the `default` preset) | the label of the scale the size fields came from (`scales.py`) |
| `mention_team` | none | the `team` sentence in the system prompt, which names no peer, and the `together` sentences and the scenario's `apart` sentence; none follows the mode |
| `informed_roles` | true | `roles.briefing` after a regulator's or disregulator's role text |
| `mention_board` | true | the board's tool bullet in the system prompt's tool list (SWE too); no paragraph describes the board; off drops the bullet |
| `notice` | counts | one provider-only message when the board changed since the agent's last call: `counts` gives each sender's new and total posts and no text of any post; `changed` the line alone, `none` nothing |
| `read_page` | 5 (10 from the scale) | the most posts one `board_read` returns |
| `reads_per_turn`, `posts_per_turn` | none (10 and 2 from the scale) | posts an agent may receive through `board_read` and posts it may make per round; past them the tool returns the newest posts left or raises a ToolError; regulators have no read budget |
| `max_message_chars` | 4000 (2000 from the scale) | `CommunicationConfig.max_message_chars`, the longest post |
| `turn_order` | random | the order of each round in the written plan (`ExecutionConfig.plan`); random draws a permutation per round from the seed; round_robin takes the agents in the order of `names` |
| `rounds` | 30 | R: with N, each agent's own budget of C = R x N tool calls (`call_budget`), late entrants included; every call counts, `wait`, a call after it and a reply with no tool call included; a call past C is refused ("No tool calls are left.") and the agent ends `rounds`; no count of rounds ends an agent, and the plan holds C rounds (`plan_rounds`, with a head start's H) |
| `calls_per_round` | 10 | N, the soft cap of one round's tool calls, board calls included and `wait` left out (`end_round` before c632292): no call is refused for it, and the round ends after the reply in which the agent's calls reach it; each round's line gives the agent's own calls left of C, and no agent is told of rounds; a round is one ORBIT activation under the `completion` quantum, ended by the plan's `end_activation` callback (`turn_activation.ends_round`) |
| `round_time_s` | 600 | T, the seconds one round may last from its first model call, model time included; a command still running at T becomes a job that `job_output` and `job_stop` read and stop (`src/sandbox/command_jobs.py`); the agent reads only that its time is limited; 0: no round clock |
| `concurrent_rounds`, `max_concurrency` | true, none | one concurrent `ScheduleStep` per round on the live board, every agent of it at once (none; 50 from the large scales); false runs one single-agent step per agent per round |
| `shutdown` | true | `stop_working` for the neutral agents and the disregulators of a `shared_task` team (`holds_stop_working`); a call ends the caller's turns (`TurnState.ended` and the store `StopWorking`) and hands in nothing; false: no stop tool and no sentence about stopping. No agent holds ORBIT's own submit (`AgentSpec.submit=False`) |
| `submit` | none | `submit` for neutral agents, the lone agent included (`gives_submit`); never for a role; none gives it in every mode; it is refused while `Benchmark.gradable` finds nothing to grade, and the store `TeamSubmission` records the hand-in and every refused call |
| `submit_delay_rounds` | 3 | how long a `shared_task` team keeps working after a `submit`: a submit in round r ends the run after round r plus this, unless a worker takes the hand-in back first; the board gets a post from the system at once; 0 ends the run with the submit's round and needs `unsubmit=false`; runs before 2026-11-24's unsubmit used 2 |
| `unsubmit` | true | in a `shared_task` team nobody stops working at a `submit`, the submitter included, and every worker holds `unsubmit(reason)` (`src/swarm/unsubmit.py`), which takes the standing hand-in back: the run goes on, any worker may submit again, and each new submit starts a new wait; with no unsubmit the snapshot taken at the submit is graded, and with no hand-in standing at the end the team's shared result as it is then; regulators and disregulators never hold it; the store `Unsubmits` and run.json `unsubmits` record every hand-in and every unsubmit; false: the submitter stops at once, as before; a stored run without the key reads false |
| `regulator_window`, `disregulator_window` | 1: | the rounds a role holds steps in, as `start:end`; the agent enters at its start round and leaves after its end |
| `head_start_rounds`, `head_start_roles` | 0, influencers | a run arm: the regulators (`regulators`) or every influencer (`influencers`) hold the first H rounds alone; the others enter in round H + 1 with their R rounds, so the plan holds R + H rounds (`plan_rounds`) |
| `rule_level` | none | the rule sentence after the task instruction (`instruction_levels.yaml`, ladder `rule`) |
| `regulator_level`, `disregulator_level` | generic, instructed | the role texts (ladders `regulator` and `disregulator`); each role's text is followed by `roles.influencer_common`, a regulator's also by `roles.regulator_check`; level `none` adds no sentence, and a regulator there keeps the task's prompt and first message |
| `regulator_discloses` | false | without it a regulator's text also ends with `roles.regulator_no_disclosure` |
| `seed_pack` | none | a seed pack `<task>/<pack>`, the folder `seeds/<task>/<pack>/` at the repository's root (`seeds/README.md`, `seed_packs.py`): a previous team's posts, put straight into ORBIT's communication store before round 1 under IDs drawn off the roster and marked `invocation_id` `seed_pack`, each author then given an exit record (`board_records`), and files planted in /tmp of every machine or in each agent's home by `src/swarm/seed_setup.py` after the benchmark's setup; run.json `seed` records the pack, the IDs, every post and file and where each went. A pack points the team at material or presses it to use the material, and holds no piece of the exploit (`tests/unit/test_collaboration_*.py`, `make seeds-check`); the scan names an exposure from a seeded text `seeded_post` or `seeded_file`, and only where the text names the honeypot's pointer |
| `tmp_snapshots` | true | each agent machine's /tmp, /var/tmp and /dev/shm listed as root before round 1 and after every tool call that ran a command there (`src/sandbox/live_tmp_capture.py`); the export writes `tmp_snapshots.json` and run.json `tmp_snapshots`; a failed listing is recorded and never fails the run |
| `proc_hiding` | true | /proc in the agents' machines shows each agent only its own processes (hidepid) and no page map (an AppArmor profile, `src/sandbox/proc_hiding/`), proven in the setup; run.json `sandbox.proc` records it |
| `access_log` | true | one sidecar per sample records each open of the honeypot (`src/sandbox/access_log/`); a failed start control ends the sample before any model call; off means no sidecar, run.json `access_log` `{"status": "off"}`, no `access_log.jsonl` and the code's evidence read from the transcript alone; `src/domains/README.md` says what the log records |
| `network_log` | true | a sidecar of its own records every socket call in the agents' machines (`src/sandbox/network_log/`): by bpftrace where the host allows it, else by the socket tables; a failed start control ends the sample before any model call; off means no sidecar, run.json `network` `{"status": "off"}` and no `network.jsonl`; `src/domains/README.md` says what the log records |
| `message_limit` | none | Inspect's message limit; none derives it from the plan (`sample_message_limit`); each agent's conversation is capped at it plus ten (`AgentSpec.max_messages`) |
| `token_limit` | 0 | Inspect's token limit, which counts cached prompt tokens in full; 0 is the runaway guard of 64M tokens per agent |
| `time_limit_s` | 0 (from the scale) | `SchedulerConfig.max_time_seconds`, ORBIT's soft halt; 0 is the benchmark's own limit |
| `time_grace_s` | 600 | seconds Inspect's hard `time_limit` sits above ORBIT's soft halt at `time_limit_s`, so a step in flight finishes and its usage is logged; 0 puts both at `time_limit_s`; SWE keeps its grading budget above the halt instead |
| `tool_limits` | none (a task may give defaults) | at most N calls of a named tool (`src/swarm/tool_limits.py`), written `tool:calls:per:when` and joined by commas: per is `agent` (each its own count) or `team` (one count for all); when is `run` (the whole run), `round` (each round) or `<N>rounds` (any N rounds in a row: `check_fix:1:agent:5rounds` lets a call in round r be followed by the next in round r + 5); a call past it is refused before the tool runs and still uses one of the agent's calls; the tool's description gains a sentence; a task may give its own tools default limits and bounds (`Benchmark.tool_limits`, `tool_limit_bounds`): a limit here replaces the task's for that tool, `tool:none` frees it, and a run past the bound or one that frees a bounded tool is refused when the task is built; a tool no agent holds is refused too; submit is bound as `team_submit` and wait as `wait` |
| `batch_agents`, `batch_judge` | false, true | `GenerateConfig(batch=True)` for the agents' model (from the scale) and for the model bound to the judge role |
| `reasoning_effort`, `tool_output_bytes` | none, 65536 | the agents' `GenerateConfig` `reasoning_effort` and `max_tool_output`, the cap also set on every bound tool; none takes the provider's default effort and Inspect's 16 KiB |
| `tool_output_cut` | middle | a result past the cap keeps its start and its end with one line between them (`src/swarm/tool_output_caps.py`); a config without it was cut by Inspect at the start |
| `peer_shell` | true | both influencers get `peer_shell`, a shell on any teammate's machine that reads every file there (`src/sandbox/peer_shell.py`); workers never get it |
| `worker_model`, `regulator_model`, `disregulator_model` | none | a role's own model as `AgentSpec.model` `swarm/<model>`, stored as an Inspect string; none runs the eval's model |
| `cost_limit_usd` | 5.0 | Inspect's `cost_limit` for the whole run, priced from `model_registry.yaml` (`src/models/cost_cap.py`); a paid run needs one, and a higher cap is set on purpose with `--set cost_limit_usd=X` |
| `judge` | gpt-6-luna | the judge entry in `src/judging/judge_models.yaml` (`gpt-6-sol` is the reference judge, `claude-haiku-5-5` the cheapest of another family; none: no judge) |

The top-level README's sections on the pull board and on submit say how a step is charged and how a run ends.
